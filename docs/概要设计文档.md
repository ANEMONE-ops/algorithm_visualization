## 二、概要设计

### 2.1 系统定位

算法过程可视化系统是一个集算法执行过程可视化、交互式学习控制、AI 智能辅导、算法横向对比、知识库学习于一体的综合性算法教学平台。系统采用 B/S（Browser/Server）架构，前端基于原生 Web 技术（HTML5/CSS3/ES6+），后端基于 Python FastAPI 框架，AI 能力通过豆包大模型（火山方舟 API）提供。

系统面向算法学习者与教育者，旨在通过"所见即所得"的可视化方式，将抽象的算法执行过程转化为直观的图形化展示，降低算法学习的认知门槛。

---

### 2.2 系统范围

**系统包含（V1.0）：**

| 序号 | 功能模块 | 说明 |
|------|---------|------|
| 1 | 5 大类 6 种算法的完整执行过程可视化 | 排序算法（冒泡/快速）、图算法（Prim MST）、树结构（哈夫曼）、递归（汉诺塔）、回溯（图着色） |
| 2 | 交互式播放控制系统 | 单步前进/回退/自动播放/暂停/重置/速度调节（0.5x ~ 5.0x） |
| 3 | 基于豆包大模型的 AI 智能问答 | 算法知识问答、步骤讲解（教程模式）、上下文感知 |
| 4 | 用户认证 | 注册/登录/JWT Token 认证（HS256，60分钟过期） |
| 5 | 算法对比视图 | 双栏同步播放，支持不同算法使用相同或不同输入数据对比 |
| 6 | 知识库 | 6 种算法的完整教程 + 13 道例题解析（含详细解题步骤） |
| 7 | 执行日志记录与 Excel 导出 | 自动保存执行记录，支持单条/批量导出 .xlsx（带样式） |
| 8 | 用户自定义测试数据管理 | 保存/删除/查询自定义测试用例到数据库 |

**系统不包含（V1.0）：**

- 自定义算法的上传与解析
- 多人协作/社交功能
- 移动端 App
- 代码编辑与在线运行
- 在线判题系统

### 2.3 设计目标

| 设计维度 | 目标 | 实现策略 |
|---------|------|---------|
| 可扩展性 | 新增算法边际成本低 | 基于 AlgorithmEngine 抽象基类 + ALGORITHM_REGISTRY 注册表，新增算法只需 3 步 |
| 可维护性 | 模块职责单一，耦合度低 | 前后端均按功能模块拆分，遵循单一职责原则 |
| 可复用性 | 可视化组件可跨算法共享 | 统一的 StepInfo 数据模型 + 5 种渲染模式（柱状图/SVG节点图/SVG树/汉诺塔DOM/图着色SVG） |
| 性能 | 步骤生成 < 500ms，切换 < 50ms | 算法预执行生成全量步骤，前端仅做索引切换（O(1)） |
| 可用性 | 5 分钟内完成首次算法执行 | 统一操作流程（选算法→输数据→运行→播放）+ 内置知识库 + AI 辅助 |

### 2.5 架构设计决策

| 决策点 | 方案选择 | 理由 |
|--------|---------|------|
| 架构模式 | B/S 三层架构 | 零安装、跨平台、浏览器即用 |
| 前端方案 | 原生 HTML/CSS/JS | 无框架依赖，加载快，适合教学场景，学生可直接查看源码 |
| 后端框架 | FastAPI | 异步高性能、自动 OpenAPI 文档、类型安全、依赖注入优雅 |
| 数据库 | SQLite | 轻量级、零配置、适合单机教学部署 |
| ORM | SQLAlchemy 2.0 | 成熟稳定、声明式模型、会话管理 |
| 可视化技术 | SVG + CSS DOM | 浏览器原生支持、无需 Canvas/WebGL 额外学习 |
| 算法执行策略 | 预执行生成全量步骤 | 支持任意跳转、无需重新计算、前进回退均为 O(1) |
| AI 集成 | 后端代理模式 | 保护 API Key、统一降级处理、60s 超时 |
| 认证方案 | JWT (HS256) | 无状态、适合前后端分离、60分钟过期 |
| 步骤数据模型 | 完整快照 (data_snapshot) | 支持双向跳转而不重新执行算法 |

### 2.7 技术选型理由详细说明

#### 2.7.1 FastAPI 选型理由

1. **异步原生支持**：async/await 原生支持，AI 对话接口调用豆包 API 时可非阻塞等待，不占用服务器线程
2. **自动 API 文档**：自动生成 OpenAPI (Swagger) 文档，开发调试效率高（访问 `/docs` 即可）
3. **Pydantic 集成**：请求/响应自动校验，类型安全，减少 80% 参数校验代码
4. **高性能**：基于 Starlette ASGI 框架，性能接近 Node.js/Go
5. **依赖注入**：`Depends(get_db)` 和 `Depends(get_current_user)` 优雅管理数据库会话和认证

#### 2.7.2 原生前端方案选型理由

1. **零依赖**：不需要 npm/webpack/babel 等构建工具链，克隆即用
2. **加载快**：首屏加载仅 HTML+CSS+JS（总计约 80KB），无框架运行时开销
3. **适合教学**：学生可直接查看源码学习，无框架黑盒，便于理解前后端交互原理
4. **SVG 原生支持**：浏览器对 SVG 的原生支持已足够强大，支持 circle/line/text/path 等元素

#### 2.7.3 预执行步骤策略选型理由

```
传统方案（实时执行）：                  本系统方案（预执行全量步骤）：

  用户点击"下一步"                      用户点击"运行"
    → 后端执行一步                        → 后端一次性执行全部
    → 返回当前状态                        → 返回完整步骤数组
    → 前端渲染                            → 前端缓存所有步骤
  缺点：回退需重新计算                  优点：前进/回退均为 O(1)

  用户点击"上一步"                      用户点击"下一步"
    → 需要重新从头执行到 i-1              → 索引 i+1，直接取 steps[i+1]
    → 耗时，尤其递归算法                  → 渲染，耗时 < 50ms
```

### 2.15 算法注册表设计

算法注册表 `ALGORITHM_REGISTRY` 是系统的核心扩展点，采用字典结构集中管理所有算法元数据：

```python
ALGORITHM_REGISTRY = {
    "algorithm_id": {
        "name": "算法中文名称",           # 显示名称
        "category": "算法分类",           # 排序/图/树/递归/回溯
        "engine": EngineClass,           # 算法引擎类（未实例化）
        "difficulty": "难度等级",         # 低-中/中/中-高
        "time_complexity": "O(...)",     # 时间复杂度
        "space_complexity": "O(...)",    # 空间复杂度
        "description": "算法描述",        # 中文简介
        "input_fields": [               # 输入字段定义
            {
                "name": "字段名",
                "label": "显示标签",
                "type": "类型",            # array/number/matrix/string
                "placeholder": "提示文本",
                "min": 最小值,             # 可选
                "max": 最大值,             # 可选
            }
        ],
    }
}
```

**注册的 6 种算法：**

| 算法 ID | 名称 | 分类 | 难度 | 时间复杂度 | 空间复杂度 |
|---------|------|------|------|-----------|-----------|
| `bubble_sort` | 冒泡排序 | 排序算法 | 低-中 | O(n²) | O(1) |
| `quick_sort` | 快速排序 | 排序算法 | 中 | O(n log n) | O(log n) |
| `mst` | 最小生成树 (Prim) | 图算法 | 中 | O(V²) | O(V) |
| `huffman` | 哈夫曼树 | 树结构 | 中 | O(n log n) | O(n) |
| `hanoi` | 汉诺塔 | 递归 | 中-高 | O(2ⁿ) | O(n) |
| `graph_coloring` | 图着色 (回溯法) | 回溯 | 中-高 | O(m^V) | O(V) |
