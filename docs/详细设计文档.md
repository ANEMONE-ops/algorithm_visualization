#### 3.1.2 密码安全设计

```
密码处理流程:
  password = "myPass123"
       │
       ▼
  salt = "algo_viz_salt_"     ← 固定盐值
       │
       ▼
  combined = "algo_viz_salt_myPass123"
       │
       ▼
  hashlib.sha256(combined.encode()).hexdigest()
       │
       ▼
  "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
       │
       ▼
  存入 users.password_hash (VARCHAR 128)
```

**JWT Token 结构：**
```json
{
  "user_id": 1,
  "username": "demo_user",
  "exp": 1719000000,
  "iat": 1718996400
}
```
- 签名算法：HS256
- 过期时间：60 分钟
- 存储方式：前端 `localStorage`，请求时通过 `Authorization: Bearer <token>` 发送

### 3.3 AI 对话降级策略

```
调用豆包 API
    │
    ├── 成功 (200) ──────────> 返回 ChatResponse(reply, model)
    │
    ├── 超时 (TimeoutException, 60s)
    │   └── 返回 "[离线模式] AI服务请求超时（60秒），请检查网络连接后重试"
    │       + 用户问题摘要
    │       + 建议: 查看算法详情面板 / 使用预设测试用例
    │
    ├── 连接错误 (ConnectError)
    │   └── 返回 "[离线模式] 无法连接到AI服务: {error}"
    │
    ├── HTTP 错误 (status != 200)
    │   └── 返回 "[离线模式] API返回状态码 {code}: {detail}"
    │
    └── 其他异常
        └── 返回 "[离线模式] AI服务异常: {error}"
```

**降级设计原则：**
- 所有异常均被捕获，绝不向用户暴露原始错误堆栈
- 降级回复包含用户问题的摘要，便于用户确认问题已提交
- 降级回复引导用户使用离线可用功能（知识库、测试用例、算法详情面板）
- 教程模式降级时直接返回步骤原文描述（不调用 AI）

### 3.4 渲染策略矩阵

| 算法 | 渲染方式 | 核心技术 | 数据结构 | 关键视觉元素 |
|------|---------|---------|---------|------------|
| 冒泡排序 | 柱状图 + CSS 过渡 | DOM + CSS transition | 数组 | 橙色高亮=比较/交换中，绿色=已排序 |
| 快速排序 | 柱状图 + 分区边界 | DOM + CSS transition | 数组 | 红色=基准元素，橙色=比较中，蓝色=未处理 |
| Prim MST | SVG 圆形节点图 | SVG circle/line/text | 邻接表 | 绿色节点=已访问，蓝色=未访问，实线绿边=MST，虚线橙边=候选 |
| 哈夫曼树 | SVG 递归二叉树 | SVG circle/line/text | 树节点（含合并历史） | 橙色=当前合并节点，灰色=叶子节点，边标0/1 |
| 汉诺塔 | CSS 柱子+盘子 | DOM div 定位 | 三柱数组 | 盘子宽度∝大小，6色循环区分，动画移动 |
| 图着色 | SVG 圆形节点图 | SVG circle/line/text | 邻接表 | 节点颜色=分配的颜色，橙色边框=当前处理顶点 |

### 3.6 播放控制状态机

```
                    ┌────────────────────────────────────┐
                    │        PlaybackController           │
                    │        (controls.js)                │
                    ├────────────────────────────────────┤
                    │  + steps: Array<StepInfo>          │
                    │  + currentStepIndex: number        │
                    │  + isPlaying: boolean              │
                    │  + speed: number (0.5 ~ 5.0)       │
                    │  + tutorialMode: boolean           │
                    │  + timerId: number|null            │
                    ├────────────────────────────────────┤
                    │  + init(steps)                     │
                    │  + next()                          │
                    │  + previous()                      │
                    │  + play()                          │
                    │  + pause()                         │
                    │  + reset()                         │
                    │  + setSpeed(speed)                 │
                    │  + goToStep(index)                 │
                    │  + toggleTutorialMode()            │
                    │  + getCurrentStep() -> StepInfo    │
                    │  + getProgress() -> {curr, total}  │
                    └────────────────────────────────────┘

状态转换图:

    ┌──────────┐    init(steps)    ┌──────────────┐
    │   IDLE   │──────────────────>│   READY      │
    │ (初始态) │                   │ currentIdx=0 │
    └──────────┘                   └──┬───┬───┬───┘
                                     │   │   │
                           ┌─────────┘   │   └──────────┐
                           │             │              │
                    next() │    play()   │    reset()   │
                           ▼             ▼              │
                    ┌──────────┐  ┌──────────┐         │
                    │ STEPPING │  │ PLAYING  │         │
                    │ idx+=1   │  │ 定时器   │         │
                    │ 渲染步骤 │  │ 自动next │         │
                    └──────────┘  └────┬─────┘         │
                           ▲           │               │
                           │  pause()  │  next()/      │
                           │           │  previous()   │
                    ┌──────┴───────────┴──┐            │
                    │ 边界条件检查:       │            │
                    │ - idx==0 → 禁用回退│            │
                    │ - idx==N-1 → 禁用前进│          │
                    │ - 播放中禁用手动控制│            │
                    └─────────────────────┘            │
                                                       │
                    reset() ←──────────────────────────┘
                    (回到 READY, idx=0)

自动播放定时器逻辑:
  interval = BASE_INTERVAL / speed
  BASE_INTERVAL = 1000ms (speed=1.0)
  speed=0.5 → 2000ms/步
  speed=2.0 → 500ms/步
  speed=5.0 → 200ms/步
```

### 3.10 对比同步机制

```
同步播放流程:
    │
    ├── 两个算法各自独立执行，生成各自的步骤序列
    │
    ├── CompareView 维护两个 PlaybackController 实例
    │   controllerA = new PlaybackController(stepsA)
    │   controllerB = new PlaybackController(stepsB)
    │
    ├── 同步播放: 统一定时器驱动
    │   setInterval(() => {
    │     if (controllerA.hasNext()) controllerA.next()
    │     if (controllerB.hasNext()) controllerB.next()
    │   }, BASE_INTERVAL / speed)
    │
    ├── 各自独立渲染
    │   VizRenderer.render(algoA, controllerA.getCurrentStep(), leftPanel)
    │   VizRenderer.render(algoB, controllerB.getCurrentStep(), rightPanel)
    │
    └── 任一算法完成后，该侧停止更新，另一侧继续
```

**后端对比 API 设计：**
- `POST /api/compare/run` — 指定两个算法和各自的输入数据，独立执行后返回两组步骤
- `POST /api/compare/run-same-input` — 两个算法使用相同输入数据（适用于同类算法对比）
- 对比结果包含：算法名称、复杂度、总步数、执行耗时、步骤数组、结果

### 3.16 核心数据流结构 — StepInfo 详解

```python
@dataclass
class StepInfo:
    step_index: int                    # 步骤序号（从0开始）
    step_type: StepType                # 步骤类型枚举（12种）
    description: str                   # 中文步骤描述
    data_snapshot: Any = None          # 当前数据完整快照
    highlights: List[int] = []         # 主高亮位置列表（橙色）
    highlights_secondary: List[int] = [] # 次要高亮列表（绿色/蓝色）
    variable_states: Dict[str, Any] = {} # 变量状态（如 i, j, pivot, depth）
    extra_info: Dict[str, Any] = {}    # 额外信息（如 before/after 快照）
```

**StepType 枚举（12种）：**

| 枚举值 | 字符串值 | 用途 | 使用算法 |
|--------|---------|------|---------|
| COMPARE | `"compare"` | 比较操作 | 排序、MST |
| SWAP | `"swap"` | 交换/移动操作 | 排序、汉诺塔 |
| SELECT | `"select"` | 选择操作 | MST、哈夫曼、图着色 |
| UPDATE | `"update"` | 更新/分配操作 | 排序、MST、图着色 |
| COMPLETE | `"complete"` | 算法完成标记 | 所有算法 |
| INIT | `"init"` | 初始化步骤 | 所有算法 |
| RECURSE_ENTER | `"recurse_enter"` | 进入递归 | 快排、汉诺塔 |
| RECURSE_EXIT | `"recurse_exit"` | 退出递归 | 快排、汉诺塔 |
| BACKTRACK | `"backtrack"` | 回溯操作 | 图着色 |
| MERGE | `"merge"` | 合并操作 | 哈夫曼树 |
| SPLIT | `"split"` | 分割操作 | 预留 |
| INFO | `"info"` | 信息说明 | 所有算法 |

### 3.27 AI 辅助的局限性与缓解措施

| 局限性 | 表现 | 缓解措施 |
|--------|------|---------|
| 理解偏差 | AI 对代码的语义理解可能不够精确 | 以实际代码为唯一事实来源，所有图表从代码推导 |
| 细节遗漏 | 可能忽略边界条件和异常处理 | 人工逐项核查所有 API 端点、错误码和边界情况 |
| 图表美观度 | ASCII 图表对齐可能不够完美 | 人工调整布局和视觉层次 |
| 版本漂移 | 代码更新后文档可能滞后 | 文档中标注版本号，要求与代码一同维护 |
| Prompt 敏感性 | 不同的 Prompt 措辞可能产生不同质量的结果 | 为每个设计阶段编写标准化 Prompt 模板 |

### 3.28 AI 辅助设计的最佳实践总结

1. **渐进式生成**：先总体架构 → 再模块设计 → 最后接口细节，逐层深入
2. **代码驱动**：以实际代码为唯一事实来源，图表从代码推导而非凭空创建
3. **交叉验证**：类图 ↔ 代码、时序图 ↔ 代码、API 规范 ↔ 路由定义，两两交叉验证
4. **人工审核**：AI 生成的内容 100% 经过人工审核，特别是技术细节和图表准确性
5. **版本标记**：在文档中明确标注 AI 参与程度和使用的模型版本，便于追溯
6. **Prompt 工程**：为每个设计阶段编写专门的 Prompt，明确输入、输出格式和质量标准
